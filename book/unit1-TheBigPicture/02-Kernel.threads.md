# 02-Kernel.Threads

#### در سیستم عامل لینوکس، کارهایه پردازشی به دو بخش اصلی تقسیم میشوند:
- ا-<mark>User-Space</mark> : برنامه هایه معمولی، سرورها(مانند nginx)،مرورگرها و ابزارهای کاربر
- ا- <mark>Kernel-space</mark> : هسته لینوکس که وظیفه ی مدیریت سخت افزار،حافظه و فرآیند ها را دارد.
-- 
- هسته لینوکس کارهای متعددی دارد که باید در پس زمینه (Asynchronously)اجرا شوند:مانند:
- مدیریت نوشتن دادها روی دیسک (Disk I/O)
- پاکسازی حافظه رم پرشده و انتقال داده ها به Swap
- مدیریت بار پردازنده(Cpu balancing)و کنترل سنسورهایه حرارتی
--
## هسته لینوکس چطور این تسک‌های سنگین و طولانی را بدون قفل کردن کل سیستم اجرا می‌کند؟

---
### ## Kernel Thread چیست؟

کرنل‌تردها وظایف مستقلی در سطح هسته هستند که:

- **شبیه فرآیند عادی (Process):** توسط همان زمان‌بند هسته (Linux Process Scheduler) مانند پردازش‌های عادی زمان‌بندی و اجرا می‌شوند.
- **تفاوت با پردازش عادی:**
    1. کاملاً در **Kernel Space** اجرا می‌شوند و هیچ فضای آدرس کاربری (No User Address Space) ندارند.
    2. دسترسی کامل و مستقیم به حافظه سیستم و دستورات سطح سخت‌افزار دارند.
    3. به هیچ فایل اجرایی روی دیسک (مانند یک فایل باینری در `/usr/bin`) وابسته نیستند؛ بلکه کدهای کامپایل‌شده‌ی درون هسته هستند.

| ویژگی | User Process (پردازش کاربر) | Kernel Thread (نخ هسته) |
| :--- | :--- | :--- |
| **محل اجرا** | User Space (محدود) | Kernel Space (دسترسی کامل) |
| **فضای آدرس (mm_struct)** | دارد (حافظه اختصاصی مجازی) | ندارد (`mm == NULL` - از فضای حافظه کرنل استفاده می‌کند) |
| **نمایش در CLI** | نام عادی (مثل `python`, `nginx`) | همیشه داخل براکت (مثل `[kthreadd]`, `[kswapd0]`) |
| **امکان System Call** | بله (برای دسترسی به هسته باید Call بزند) | خیر (خودش بخشی از هسته است) |
| **Crash کردن** | فقط خودش بسته می‌شود (Segfault) | ممکن است منجر به Kernel Panic و ریست سیستم شود |

## 4. مهم‌ترین Kernel Threadها در لینوکس

اگر دستور `ps -ef` یا `ps aux` را اجرا کنید، پردازش‌هایی با علامت `[ ]` مشاهده می‌کنید. مهم‌ترین آن‌ها عبارتند از:

### ۱. `[kthreadd]` (PID = 2)

- **پدر تمام Kernel Threadها:** بعد از بوت اولیه هسته، به عنوان نخ شماره ۲ ساخته می‌شود و وظیفه ساخت و راه‌اندازی سایر نخ‌های کرنل را بر عهده دارد.

### ۲. `[kswapd0]`

- **مدیر حافظه (Page Reclaimer):** اگر رم پر شود، این ترد بیدار شده و صفحه‌های کم‌مصرف حافظه را به دیسک Swap منتقل می‌کند تا حافظه آزاد شود.

### ۳. `[kblockd]`

- **مدیر I/O دیسک:** درخواست‌های بلوکی برای خواندن و نوشتن روی درایوها (SSD/HDD) را زمان‌بندی و به صف می‌کند.

### ۴. `[kcompactd0]`

- **یکپارچه‌ساز حافظه (Memory Compaction):** از تکه‌تکه شدن (Fragmentation) صفحات حافظه جلوگیری می‌کند تا فضاهای یکپارچه بزرگ برای برنامه‌ها فراهم شود.

### ۵. `[migration/X]`

- **توزیع بار هسته‌ها:** مسئول انتقال (Migrate) پردازش‌ها بین هسته‌های مختلف CPU برای تقسیم عادلانه بار پردازشی.
