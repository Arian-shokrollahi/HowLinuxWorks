## سطوح و لایه‌ها در سیستم لینوکس

### ایده اصلی: Abstraction (انتزاع)

سیستم کامپیوتری خیلی پیچیده‌ست. برای اینکه راحت‌تر بفهمیمش، اون رو به **لایه‌ها (Layers)** تقسیم می‌کنیم:

- بالاترین لایه: برنامه‌هایی که مستقیم باهاشون کار می‌کنیم (مرورگر، بازی)
- پایین‌ترین لایه: سخت‌افزار و همون صفر و یک‌های حافظه
- سیستم‌عامل (لینوکس) بین این‌ها قرار می‌گیره

### سه سطح اصلی در لینوکس (از پایین به بالا):

**۱. Hardware (سخت‌افزار)** 🔩

- CPU، حافظه اصلی (RAM)، دیسک‌ها، کارت شبکه
- یعنی همه‌ی قطعات فیزیکی

**۲. Kernel (هسته)** 🧠

- قلب سیستم‌عامل؛ یک نرم‌افزار که توی حافظه ساکنه
- نقشش مثل **میانجی (mediator)** هست: به CPU میگه چیکار کنه، سخت‌افزار رو مدیریت می‌کنه
- تنها رابط بین برنامه‌ها و سخت‌افزار همینه
- داخلش: System Calls، مدیریت پردازش (Process Management)، مدیریت حافظه (Memory Management)، درایورها

**۳. User Space (فضای کاربر)** 👤

- همه‌ی برنامه‌های در حال اجرا (Process) اینجا زندگی می‌کنن
- مثلاً: محیط گرافیکی (GUI)، سرورها، Shell
- نکته: وب‌سرورها هم User Process هستن، نه بخشی از کرنل

# تفاوت مهم kernel mod & usermod خیلی ساده
| Kernel mod                        | Usermod                             |            |
| --------------------------------- | ----------------------------------- | ---------- |
| دسترسی نامحدود به cpu و RAM       | محدود به یک بخش کوچیک حافظه         | premission |
| اگه خراب بشه کل سیستم crash میکنه | اگر خراب بشه فقط همون پردازش میمیره | risk       |
- قسمتی از حافظه که **فقط کرنل** بهش دسترسی داره → **Kernel Space**
- قسمتی که پردازش‌های کاربر می‌تونن ببینن → **User Space**
- مثال=>مرورگرت crash میشه؟ 😅 مهم نیست، فقط خود مرورگر می‌بنده — بقیه سیستم سالمه، چون کاربر فقط توی User Mode بوده. ولی اگه کرنل باگ داشته باشه، کل سیستم down میشه.

---
- «پردازش کاربر هرگز نمی‌تونه به سیستم آسیب بزنه» فقط **در تئوری** درسته! اگه یک پردازش دسترسی (permission) مناسب داشته باشه، می‌تونه مثلاً دیتای دیسک رو نابود کنه. برای همین لینوکس یه سری محافظت‌ها (safeguards) داره و بیشتر پردازش‌ها اجازه‌ی خرابکاری ندارن.
